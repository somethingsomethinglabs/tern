# Use Electron WebContentsView for the first desktop browser

The approved prototype is a React shell, but its sample pages cannot browse real sites. Tern needs independent Chromium pages that remain alive while their owning task is put aside. A full Chromium fork would require a separate browser build and maintenance effort; Tauri on Linux would change the engine to WebKitGTK.

Use Electron 44.4.3 with one retained WebContentsView per live page. The main process owns task persistence and page lifetimes. A trusted shell communicates through a small validated preload bridge; websites get no Node access, exposed shell bridge, or shell protocol handler. A sandboxed, isolated-world preload reports scroll direction for toolbar visibility and marks eligible hovered links for Chromium's native speculation rules. Same-origin link paths stay in that renderer. External hover sends only the destination origin to the host for bounded native preconnection. The host accepts these events only from the selected website's main frame; preconnection also requires a visible page, focused window and enabled preference. No page text or forms are sent to the shell. The selected page's native bounds follow a measured rectangle in the shell. See [hover preloading](../hover-preloading.md) for its selection policy and limits.

This keeps the existing visual direction and makes actual page retention testable. It also commits us to Electron security updates and explicit navigation, permission, popup, download, and unload policies. Metadata restoration reopens URLs and does not restore a live JavaScript heap. See [host research](../browser-host-research.md) for the sources and constraints.
